# HUMAN VICTORY演出とX共有導線 — Design

## Goal

50戦チャレンジで人間がAIに勝ち越した瞬間を、この作品で最も印象に残る
到達点として演出する。同時に、現在の汎用共有メニュー、画像保存、投稿文コピーに
加えてX専用の共有導線を用意し、結果を少ない操作で投稿できるようにする。

結果表示はモーダルやポップアップにせず、PLAYタブ内の横幅いっぱいの
`ChallengeResult`パネルを使う。50戦後の継続、再挑戦、LABへの導線と、
最初の50戦結果を固定する既存仕様は維持する。

## Decisions

- 人間の50戦成績が `humanWins > aiWins` のときだけ勝利演出を表示する。
- X共有は、投稿文を入力済みにしたXの投稿画面を直接開く方式とする。
- Xへの画像自動添付や自動投稿は行わない。結果画像の保存とWeb Shareを隣に残す。
- 結果画面はPLAY内のフルワイドパネルとし、モーダルにはしない。
- 日本語の主書体はOS標準のゴシック体へ変更し、機械的な印象を弱める。
- 最初の50戦スナップショットを演出、投稿文、画像の唯一の入力とする。

## Result Outcome

固定された`ChallengeResult`から表示用の結果区分を純粋に導出する。

- `human-victory`: `humanWins > aiWins`
- `ai-victory`: `humanWins < aiWins`
- `draw`: `humanWins === aiWins`

この区分は表示と共有文の分岐だけに使う。ゲームエンジン、Hedge / Fixed Share、
expert重み、永続化された50戦スナップショットの形は変更しない。

## HUMAN VICTORY Experience

### Layout

人間勝利時は、既存の`ChallengeResult`を次の構成へ変える。

1. `50 ROUNDS COMPLETE / HUMAN VICTORY`
2. 大見出し `HUMAN VICTORY`
3. 日本語メッセージ
   `勝利不能、ではなかった。50戦でAIに勝ち越しました。`
4. YOU / AI / DRAWの固定50戦スコア
5. AIが最も強く疑った仮説とHedge weight
6. 共有操作
7. 「じゃんけんを続ける」、LAB、再挑戦

背景には放射状の光と低彩度のグリッドを置き、内容の可読性を保つ。
右上または見出し付近に、少し傾けた勝利スタンプを配置する。狭い画面では
スタンプを本文と重ねず、見出し下へ移動する。

AI勝利と引き分けでは現在の分析完了レイアウトを維持し、結果に合う短い見出しだけを
表示する。祝福用の金色、紙吹雪、勝利スタンプは使わない。

### Motion

50戦目が現在の画面操作で完了し、人間が勝ち越した場合に一度だけ次を再生する。

- 背景の放射光が短く広がる。
- `HUMAN VICTORY`と勝利スタンプが小さく拡大しながら定位置へ入る。
- YOU / AI / DRAWが最終値まで短時間でカウントアップする。
- 紙吹雪が約2秒落下し、その後DOMから取り除かれる。

アニメーション中も共有や次の操作をブロックしない。リロードや
「50戦の診断を見る」で結果を再表示した場合は、完成した勝利デザインとごく弱い
背景モーションだけを表示し、紙吹雪とカウントアップは再生しない。

App側で`active -> result`のライブな状態遷移を検出して、`ChallengeResult`へ
一時的な`celebrate`フラグを渡す。このフラグは保存しないため、既存storage schemaを
変更せずにリロード時の再演を防ぐ。

`prefers-reduced-motion: reduce`では紙吹雪、カウントアップ、拡大、背景モーションを
停止し、最初から最終状態を表示する。紙吹雪は装飾として支援技術から隠す。
スコアの読み上げには、常に最終値を持つ別のアクセシブルなテキストを使う。

## Typography

Google FontsのManropeを日本語UIの主書体として使うのをやめ、次のような
OS標準の日本語ゴシックを優先する。

`"Hiragino Sans", "Yu Gothic", "YuGothic", "Meiryo", system-ui, sans-serif`

英数字の計測値、expert ID、補助ラベルには既存の等幅書体を限定的に残す。
大見出しも極端に未来的な字間にはせず、日本語本文との一体感を優先する。
Canvasで生成する結果画像も同じフォント方針に合わせる。

## X Share

### Primary action

結果画面の共有操作の先頭に`Xでシェア`を置く。通常のリンクとして
新しいタブでXの投稿画面を開き、`noopener noreferrer`を指定する。
リンク先は`https://x.com/intent/post?text=...`とし、固定50戦結果から生成した
投稿文全体を`text`へURLエンコードする。

投稿文には次を含める。

- 結果に応じた一行目
- YOU / AI / DRAWの固定50戦スコア
- サイトURL
- `#勝利不能じゃんけんAI`

人間勝利時の基本文面は次とする。

```text
勝利不能、ではなかった。
「勝利不能？じゃんけんAI」に50戦で勝ち越しました。

YOU 〇勝 / AI 〇勝 / DRAW 〇回
https://...
#勝利不能じゃんけんAI
```

AI勝利と引き分けでは、現在の「AIに疑われた仮説」を含む投稿文を維持する。
仮説は事実として断定せず「疑われました」と表現する。

X Web Intentではブラウザ内で生成したPNGを自動添付しない。投稿画面を開く操作と
画像保存を一つのクリックへ束ねると予期しないダウンロードになるため、別操作として
明示する。

### Other share actions

操作は次の順とする。

1. `Xでシェア`
2. `画像付きでシェア`
3. `結果画像を保存`
4. `投稿文をコピー`

`画像付きでシェア`は既存のWeb Share APIを使い、対応環境では生成PNGを含める。
ファイル共有に対応しない環境ではテキストとURLを共有する。
Web Share自体がない環境でもX、画像保存、投稿文コピーは残す。

Web Shareへ`url`を別フィールドで渡す場合は本文から同じURLを除き、共有先での
URL重複を防ぐ。X用、クリップボード用、Web Share用の文面は共通の結果情報から
用途別に生成する。

## Share Image

人間勝利時の1200×630 PNGにも画面と同じ勝利表現を適用する。

- `HUMAN VICTORY`
- `勝利不能、ではなかった。`
- YOU / AI / DRAW
- `50 ROUNDS`
- サイト名と英語サブタイトル

AI勝利と引き分けでは、現在の仮説中心の結果画像を維持する。
静的OGPは個別結果を持てないため、現在のサイト共通OGP画像をそのまま使う。
X投稿にURLだけが含まれる場合は、この共通OGPがリンクカードとして使われる。

## Components and Boundaries

- challenge domain:
  - 固定結果から`human-victory`、`ai-victory`、`draw`を返す純粋関数
- `App`:
  - ライブな50戦完了遷移だけを検出し、非永続の`celebrate`を渡す
- `ChallengeResult`:
  - 結果区分ごとの見出し、勝利装飾、操作群を表示する
- `VictoryCelebration`:
  - 紙吹雪、放射光、スタンプなどの装飾を担当する
- sharing module:
  - 用途別投稿文、X Web Intent URL、結果PNGを生成する純粋処理

外部SDKやX認証は追加しない。共有のために対戦履歴やexpert重みを外部へ送信しない。

## Accessibility and Responsive Behavior

- 結果見出しへの既存フォーカス移動を維持する。
- 勝利は色やアニメーションだけでなく、`HUMAN VICTORY`と日本語文で伝える。
- 紙吹雪と放射光は`aria-hidden`にする。
- X共有はリンクとして判別できる名前を持ち、新しいタブで開くことを補助文で示す。
- 共有処理の成功、失敗は既存live regionで通知する。
- モバイルでは共有操作を一列にし、最初にX共有を置く。
- 320px相当の幅でも見出し、スタンプ、スコア、ボタンが横にはみ出さない。
- `prefers-reduced-motion`では最終状態を即時表示する。

## Error Handling

- Xリンク生成に必要な結果が存在しない場合、リンク自体を表示しない。
- ブラウザの共有キャンセルはエラー扱いにせず、現在の穏やかなstatus messageを使う。
- Canvas、Clipboard、Web Shareの失敗時も、利用可能な別の共有操作を無効化しない。
- 操作中は同じ非同期処理の連打だけを防ぎ、Xリンクと次画面への導線を不要に止めない。

## Testing

純粋関数のtestsで以下を確認する。

- 勝敗差から3種類の結果区分を正しく導出する。
- 人間勝利時だけ祝福用投稿文になる。
- X Web Intent URLが投稿文、固定50戦スコア、URL、ハッシュタグを正しく保持する。
- Web Share用テキストとURLが重複しない。
- 人間勝利PNGと通常PNGが正しい結果分岐を使う。

component / app testsで以下を確認する。

- 人間勝利時だけ`HUMAN VICTORY`と勝利スタンプを表示する。
- 50戦目のライブ完了時だけ`celebrate`が有効になる。
- リロード相当の初期表示と診断の再表示では派手な演出を再生しない。
- AI勝利と引き分けで祝福演出を表示しない。
- `Xでシェア`が正しいリンク、target、relを持つ。
- Web Share、画像保存、投稿文コピー、継続、LAB、再挑戦が残る。
- reduced motion時でも最終結果と全操作を利用できる。

完了前にlint、全test、production buildを実行する。desktopとmobileで
勝利、AI勝利、引き分け、リロード後、reduced motionを目視確認する。

## Delivery

実装と検証が完了したら、関連変更だけをコミットする。
`.superpowers/brainstorm/`の一時モックアップはコミットしない。
最終確認後、`main`をremoteへpushする。
