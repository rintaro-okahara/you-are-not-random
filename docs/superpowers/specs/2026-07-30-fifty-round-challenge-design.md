# 50戦チャレンジと共有導線 — Design

## Goal

研究デモとしての情報量と正確さを保ちながら、初見のユーザーが一瞬で
「学習するじゃんけんAI」だと理解し、50戦の挑戦、診断、共有まで迷わず
進める体験にする。

主タイトルは **「勝利不能？じゃんけんAI」**、英語サブタイトルは
**「YOU ARE NOT RANDOM」** とする。既存のダークな研究ラボ調のデザイン、
24 experts、Hedge / Fixed Shareの学習エンジンは維持する。

## Scope

- 50戦チャレンジと分析進捗
- 50戦時点の固定診断
- PLAY / LABタブ
- 結果画像の生成、共有、保存、投稿文コピー
- Open GraphとX Card用のメタデータおよび静的OGP画像
- 「信頼度」を「現在の支持度 / Hedge weight」へ修正
- 新タイトルに合わせたファーストビュー、共有文、OGPの統一

アルゴリズム、expert集合、学習率、Fixed Shareの計算方法は変更しない。

## User Experience

### Header and hero

ヘッダーとファーストビューでは「勝利不能？じゃんけんAI」を最も目立つ
主タイトルにする。「YOU ARE NOT RANDOM」はサブタイトルとして残し、
50 rounds / 24 hypothesesと、クリック前にAIの手が決まっていることを短く伝える。

### PLAY

初期表示はPLAYタブとし、次だけを優先して表示する。

- 「50回、AIに癖を見抜かれずにいられる？」という挑戦文
- 現在の進捗（例: `7 / 50`）
- じゃんけん操作
- 累積勝敗
- AIが現在最も強く疑っている仮説

分析段階は次の3段階とする。

- 0〜7戦: 分析中
- 8〜49戦: 暫定仮説
- 50戦: 診断完了

### LAB

LABタブには詳細な研究表示をまとめる。

- 全24 expertの重みと累積期待報酬
- empirical regret
- Markov遷移行列
- Fixed Share設定
- 対戦履歴
- アルゴリズムの短い説明

詳細表示を削除せず、一般ユーザー向けのPLAYから一段奥へ移す。

### Completion and continuation

50戦目の終了時に結果画面を表示し、以下を提示する。

- 50戦時点の人間勝利数、AI勝利数、引き分け数
- 50戦時点で最大重みだったexpert
- そのexpertの日本語による仮説説明
- 現在の支持度（Hedge weight）
- 結果の共有、画像保存、投稿文コピー
- LABで分析を見る
- じゃんけんを続ける
- もう一度挑戦する

「じゃんけんを続ける」は同じ学習状態で51戦目以降を再開する。
継続ラウンドは累積成績、履歴、expert重み、regretへ通常どおり反映するが、
共有用の診断結果は最初の50戦時点から変更しない。

「もう一度挑戦する」は対戦履歴、累積成績、学習統計、regret、expert重み、
固定診断を初期化し、新しい50戦を開始する。ユーザーが選んだFixed Share設定と
学習ON/OFFは維持する。従来の全リセットは、設定を含めて既定値へ戻す別操作として
LABに残す。

## State and Persistence

既存の学習状態から独立したチャレンジ状態を追加する。

- `challengeStatus`: `active`、`result`、`continued`
- `challengeResult`: 50戦目終了時の固定スナップショット、または未完了時の`null`
- `challengeBaseline`: チャレンジ開始時点の累積ラウンド数と累積勝敗
- `activeView`: `play`または`lab`

`challengeResult`は次の共有・再表示に必要な値だけを持つ。

- 診断確定時刻
- 50戦の勝敗数
- 最大重みのexpert ID
- expert名と日本語説明
- その時点のexpert重み

50戦到達時に一度だけスナップショットを作成し、51戦目以降の更新では
上書きしない。50戦後に65戦まで続けてリロードした場合、結果画面には固定された
50戦診断を表示し、学習統計とLABには65戦分の最新状態を復元する。
「じゃんけんを続ける」を押すと66戦目から再開する。

チャレンジ進捗と50戦成績は、現在の累積値から`challengeBaseline`を引いて求める。
結果確定後に「じゃんけんを続ける」を選ぶと、そのセッション中は
`challengeStatus=continued`となる。固定結果が存在する状態でページを再読み込みした
場合は、累積学習状態を維持したまま`challengeStatus=result`として初期化し、
固定結果を再表示する。

永続化schemaを更新し、既存schemaから安全に移行する。アップデート前から
50戦以上のデータがある場合、正確な50戦時点のexpert重みを復元できないため、
既存の累積データを保持したまま、現在の累積ラウンドを
`challengeBaseline`として新しい50戦チャレンジを始める。50戦未満の場合も同様に
現在値をbaselineとし、アップデート後のラウンドだけを新チャレンジへ数える。

## Sharing

共有内容はブラウザ内で生成し、対戦データを外部サーバーへ送信しない。

結果画像には次を含める。

- 勝利不能？じゃんけんAI
- YOU ARE NOT RANDOM
- 「AIが最も強く疑った仮説」と日本語説明
- YOU / AI / DRAWの50戦成績
- `50 ROUNDS / 24 EXPERTS`
- 「あなたはAIに読まれずにいられる？」

共有文は仮説を事実として断定せず、
「AIに○○の癖を疑われました」と表現する。

対応ブラウザではWeb Share APIで画像ファイルと投稿文を共有する。
画像共有に対応しない環境では、PNG保存と投稿文コピーを個別に提供する。
Web Share、Clipboard、PNG生成の失敗は画面内のstatus messageで伝え、
利用可能な代替操作を残す。

リンク共有用にはダークテーマの静的な1200×630px PNGを用意する。
`index.html`へcanonical URL、description、Open Graphの基本項目、
`twitter:card=summary_large_image`と対応するタイトル・説明・画像URLを追加する。

## Components and Boundaries

- `ChallengeProgress`: 50戦の進捗と分析段階だけを表示する。
- `ViewTabs`: PLAY / LABの選択とキーボード操作を担当する。
- `ChallengeResult`: 固定診断と結果後の操作を表示する。
- `ShareCard`: 固定スナップショットから共有画像を描画し、PNGを生成する。
- challenge domain module: 50戦到達判定、状態遷移、スナップショット、
  共有文の生成を純粋関数として提供する。

既存のゲームエンジンとオンライン学習モジュールはチャレンジUIを知らない。
React reducerがラウンド完了後にchallenge domain moduleを呼び、
学習結果とチャレンジ状態を一つのactionで更新する。

## Accessibility and Responsive Behavior

- PLAY / LABはタブのrole、選択状態、関連panelを明示する。
- タブは矢印キー、Home、Endで移動できる。
- 50戦到達時は結果見出しへフォーカスを移し、完了をlive regionでも通知する。
- 進捗、勝敗、共有結果は色だけに依存せずテキストを併記する。
- 共有処理の成功・失敗はスクリーンリーダーにも通知する。
- モバイルではPLAYの進捗、手の選択、直近結果、成績、仮説の順に縦配置する。
- `prefers-reduced-motion`では結果表示を含む装飾アニメーションを抑制する。

## Testing

純粋なchallenge domain testsで以下を確認する。

- 49戦までは結果を確定しない。
- 50戦目に一度だけ正しい勝敗と最大expertを固定する。
- 51戦目以降は固定結果を上書きしない。
- 続行、再挑戦、全リセットの状態遷移が異なる。
- 投稿文が断定表現を使わず、固定診断だけから生成される。

reducer、storage、component testsで以下を確認する。

- リロード後に固定50戦診断と50戦以降の累積学習状態を両方復元する。
- 既存schemaの累積状態を保持したまま新しいチャレンジを開始する。
- PLAY / LABの初期表示、切り替え、キーボード操作が機能する。
- 50戦到達時に結果が表示され、対戦操作が一度停止する。
- 「じゃんけんを続ける」で次ラウンドから再開する。
- 「もう一度挑戦する」が設定を維持し、学習・対戦状態だけを初期化する。
- 共有機能が非対応または失敗した場合も保存・コピーの代替導線が残る。

完了前にlint、全test、production buildを実行する。主要なdesktop幅とmobile幅で
PLAY、LAB、50戦結果、共有画像、フォーカス表示、overflowを目視確認する。

## Delivery

実装、検証、ドキュメント更新まで完了したら、変更を意図ごとにコミットする。
最終確認後、`main`をremoteへpushする。
